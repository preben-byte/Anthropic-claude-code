Marivold WiFi Audit

Dato: 2026-07-15 · Kilde: SSH-output fra fire AP460C + iPhone WiFi-info · Status: kartlegging, ingen endringer utført

Denne rapporten er både en dokumentasjon av dagens tilstand og et selvstendig handoff-dokument. Lim inn hele filen til Claude Code på PC-en for å fortsette arbeidet uten å måtte forklare konteksten på nytt.

Del 1: Kontekst

Marivold Resort, XIQ-tenant VHM-HCPDLLOM. Bruker ønsket først å heve max clients på tre AP-er fordi Adm-nettet oppleves «fullt». Diagnose viser at det egentlige problemet er (a) DHCP-scope-utnyttelse på Marivold-guest, ikke Adm, og (b) alvorlig kanalplan-feil på tvers av fire AP-er. Ingen endringer utført enda.

Bruker jobber lokalt via SSH på AP-er + GUI mot XIQ og Palo Alto. Claude Code på PC-en har ikke direkte tilgang — rollen er å gi eksakte kommandoer, GUI-oppskrifter og verifikasjonssteg.

Del 3: Klienttall (fra ARP)

  • Adm-nett (192.168.200.x): ~30 unike IP-er, 6–8 trådløse. Resten kabel.
  • Marivold-guest (192.168.202.x): 100+ unike IP-er. Nærmer seg fullt for /24.

Konklusjon: «Fullt for IP-tilkoblede enheter»-meldingen gjelder trolig guest-nettet, ikke Adm. Må bekreftes på Palo Alto DHCP.

Del 4: Kritiske funn

K1 — Kanalplan brutt (2.4GHz). Tre av fire AP-er kjører kanal 11 samtidig. Egne AP-er stjeler airtime. Resepsjon-APen viser 24 % CRC error og 66 % airtime utilization som direkte konsekvens.
K2 — Kanalplan brutt (5GHz). Toalett og Resepsjon deler kanal 157.
K3 — ACSP disabled overalt. show acsp _last-selection viser Disabled for wifi0/wifi1 på alle AP-er. Kanaler manuelt låst uten koordinering. Merk: å bare skru på ACSP gir samme resultat (alle ender på 11) fordi ekstern interferens gjør 1 og 6 dyrere. Løsning: manuell 1/6/11 basert på fysisk plassering.
K4 — 11ax-features slått av. BSS Color = 0, MU-MIMO disabled på 5GHz, A-MSDU disabled, Tx Chain static 2 på 2.4 på Resepsjon.
K5 — Firmware aldrende. X435 kjører 30.7.1.1 fra 2020. HP 2530 er 1 Gbit / 8 porter / 802.3at.
K6 — Adm-nett har 0 klienter på 5GHz. SSID kringkastes, men ingen kobler seg til (klienter er POS/skrivere som er 2.4-only). Vurder Adm som 2.4-only.
K7 — Stolpe uplinker via 192.168.1.2 (TSW202). Merkelig arkitektur. Årsak må undersøkes.

Del 5: Bra ting

  • CAPWAP til XIQ stabil (Selvinnsjekk uptime 21 dager, 843 GB tunnellet)
  • Temperatur 41–44°C på alle AP-er
  • Ingen radar detected på DFS
  • Mesh backhaul Toalett ↔ Gazastripe-Bobil-Ext fungerer

Del 7: Neste steg for Claude Code

Når du blir promptet på PC-en, kan bruker be deg om:

  1. Skriv XIQ-oppskrift for P0/P1/P2 med eksakte klikk-stier
  2. Skriv Palo Alto commit-blokk for guest-DHCP — trenger P3-output først
  3. Skriv rollback-plan før noen endring gjøres
  4. Bygg videre på scaffoldet i agents/wifi/ for å automatisere XIQ-audit (repo: preben-byte/Anthropic-claude-code, branch claude/wifi-config-optimization-tzoxnf)

Ikke gi CLI-kommandoer for IQ Engine 10.8 uten å sjekke syntax først — feil kommando kan ta radioen ned. Alle endringer skal helst inn i XIQ (overlever strømbrudd og re-provisioning).

Bruker har både Palo Alto og Cisco. Palo Alto er brannmur på .1. Cisco er ikke identifisert enda.
